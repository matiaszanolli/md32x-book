# Mars development discs and new retail ROMs — catalog

Working notes, not part of the book. All ROMs live in `../32x-playground/`; verify with `python3 ../games/tools/header32x.py` (paths relative to `notes/`).

## The dev discs

Six Sega-internal Mars discs, February-May 1994. Notes per disc:

- **Check Program** is the only one with a matching header checksum (`$8DA0`); the others are all zero. Service/diagnostic cart, full 32 Mbit — candidate evidence for the dev-systems appendix.
- **Egypt** has the tiniest SH-2 image of the set (0x1328 bytes ≈ 4.9 KB). **Not a codec test at all** — see the verification section below: its SH-2 program is a ~30-instruction page-flipping blitter for one raw 320×200 RGB frame.
- **Gnu Sierra** is the odd one: entries and VBRs live in the cached cartridge window `0x0200xxxx` like Motocross Championship, and its copy block claims `$080000`+0x40000 bytes — but the largest dump is 0xA0000 bytes, so **both circulating dumps are truncated** (the `[b1]` at 599,768 more so). Treat as incomplete until a fuller dump appears.
- **Runlength Mode Test** carries a 0x375BC-byte (227 KB) SH-2 image. It tests the VDP's hardware run-length display mode, fed by a polygon span renderer — see the dedicated section below.
- **SOJ**'s MD header says `MARS CHECK PROGRAM VERSION 1.0` (same strings as the Check Program) though it circulates as a sample; its `$1A4` end (`$3FFFFF`) exceeds the 64 KB file — truncated too, or a header reused from the 32 Mbit check image.
- `[b1]`/`[b2]` variants of Egypt, Gnu Sierra, Runlength, SOJ and Texture are byte-prefixes of the clean dumps (same headers and copy blocks, smaller files); the clean ones supersede them.
- **ECCO the Dolphin CinePak Demo** (`c2b642fd…`, 24 Mbit, checksum zero, `Version-10`): a dev demo disc, not retail — grouped here. **Verified genuine CinePak** (verification section below): Sega FILM container, `cvid` video only (**no audio**: corrected 10 October 2026, see `notes/games/ecco/ANALYSIS.md`), decoded on the SH-2 from the cache-through ROM window.

## Two entry-trampoline designs (Chaotix, MK2)

Both games put the Slave entry **4 bytes after** the Master entry — not shared startup code, just adjacent branch slots:

- **Chaotix** `$060001A0`: Master = `bra $06000884`, Slave = `bra $06000244`; `$060001A8` is a `bra`-to-self park stub. Right below at `$060001B0` sits the one-dispatcher interrupt routine with its table at `$06001D8`: eight slots, indexed `((SR>>5)<<2)&0x1C` — adjacent IRL **levels share a slot** (safe: only even levels 6/8/10/12/14 are used). Handlers: CMD(8)→`$06001334`, V(12)→`$06001280`, VRES(14)→`$06001250`, H(10)→ the park stub `$06001A8`. Confirm HEN is never set before claiming the H slot is deliberately parked.
- **Mortal Kombat II** `$06000240`: Master = `bra $0600250` into the shared init; Slave = `mov.l pool,r0; jmp @r0` → `$0600510C`. The Master init's first acts: stack/GBR set (`GBR` = system regs), then **double word-writes to `@(22,gbr)`, `@(24,gbr)`, `@(26,gbr)`, `@(28,gbr)`** — the five interrupt-clear registers cleared twice each, Sega's write-twice advice in shipped code.

Both are third/fourth retail confirmations of the one-dispatcher design (with Virtua Racing Deluxe and Motocross Championship), for `src/sh2/intc.md`.

### Chaotix runtime (headless, 500-660 frames attract)

- **Interrupt mask: `0x8202`, rock-stable across 660 frames.** Decoded per the book's register table: bit 15 FM (the SH-2s own the VDP/frame buffer — not an interrupt), bit 9 the read-only ADEN mirror, and **bit 1 CMD is the only enabled interrupt**. HEN is never set, so the dispatch table's H slot pointing at the `bra`-self park stub is unreachable by design — that question is closed. V, H and PWM are never enabled either: the 68000 paces the SH-2s through the CMD interrupt, the same pattern as Motocross Championship (third retail confirmation, for `src/sh2/intc.md` and the communication chapter).
- **The Slave is the workhorse; the Master manages the VDP.** DRC profiling: Slave ~302k useful cycles per frame (~79% of one SH-2 at 60 Hz), sleeping between CMD interrupts at `$060002F8`; Master ~1.5k cycles/frame after its one-time boot-ROM SDRAM clear (~720k cycles executing `mov.l r0,@-r8` down SDRAM). The DRC profile under-reports the Master: interpreter-mode register sampling catches it cycling through `$060030B0`, a tight `$060008F2` loop polling VDP status (GBR toggling `0x20004000`/`0x20004100` — FILL/FS waits), and `$06000A1E` bookkeeping. Reading: Master = fill/flip and scene manager, Slave = renderer. The 68000 sits in its usual wait loop (~126k cycles/frame).
- **Emulator-method lesson for the emulator-testing howto:** PicoDrive's DRC elides poll loops and reports compiled hot code at `0xC000xxxx` pseudo-PCs (77M of the Slave's cycles live there), so DRC profiles show "vanished" wait loops and inflated-looking interpreter PCs. Cross-check with interpreter-mode `regs` sampling before quoting cycle splits.

## Codec verification (4 October 2026)

**ECCO demo — CinePak, proven.** The movie is a raw Sega FILM container at ROM `$20000` (`FILM` magic; `FDSC` chunk tags the stream `cvid`, 256×160; `STAB` sample table). Structural walk of all 180 video samples: every frame is a 16-byte header (BE32 size = sample size − 8, width 256, height 160, 1 strip), then one strip `[id 0x1000][len][0][y1 0][y2 0x00A0][0x0100]`, then chunks `[id BE16][len BE16]` (length includes the 4-byte header) — per frame exactly `0x2000` (codebook, length ≡ 0 mod 4 entries), `0x2200` (header-only, empty) and `0x3000` (block-index payload), the last closing on the strip boundary to the byte. **180/180 frames validate, zero failures.** **Correction (10 October 2026):** the 16-byte `STAB` entries are `(offset, length, info1, info2)`, not interleaved audio: all 180 are video (none has info1 = 0xFFFFFFFF), contiguous, 20 ticks of a 600 Hz base each, so the file has no audio at all; `ffprobe`'s `pcm_s8` stream is its default for a 20-byte `FDSC`. Cross-check: `ffprobe`/`ffmpeg` on the extracted container report `film_cpk` + `codec_name=cinepak`, 256×160, and decode all 180 frames without error. All frames are intra (strip id `0x1000`, never `0x1100`) — the demo uses keyframes only.

The player side: the SH-2 main loop (`$060001D4`) calls `decoder(out=0x06010000, 0x200, stream=0x22020000)` once per pass — the movie is read directly from the **cache-through cartridge window** (sensible for a sequential stream; no cache pollution), decoded into SDRAM staging at `$06010000`, then blitted to the frame buffer and page-flipped through the VDP FS bit. The same FS-bit flip loop appears in Egypt's program.

### ECCO decoder deep-dive (complete, cross-verified)

The whole codec is now specified from the SH-2 code (`$06001788` frame walker → `$060010C4` strip/chunk handler → `$06000F5C` codebook converter → `$060002B4` rasterizer) and every claim cross-checked against ffmpeg's decoder output on frame 29 (luma correlation 0.996; stream consumption exact at 10,560 of 10,564 bytes, all 2,560 blocks V4):

- **Frame**: 16-byte header (BE32 size = sample size − 8; BE16 width; BE16 height; BE16 strip count), then strips. Strip: `[id 0x1000 intra / 0x1100 inter][BE16 length incl. header][BE16 0][y1][y2][width]`, then chunks.
- **Chunks**: `[BE16 id][BE16 length incl. 4-byte header]`. `0x2000` = full V4 codebook; `0x2100` = compressed V4 codebook (per-entry presence bit, absent entries keep the previous frame's); `0x2200`/`0x2300` = same for the V1 codebook; `0x3000` = block vector data. The demo emits only `0x2000`, `0x2200` (always empty) and `0x3000` — every frame is a keyframe using V4 blocks only.
- **Codebook entry** (stream): 6 bytes `[y0 y1 y2 y3 u v]` — four unsigned luma values for the 2×2, one shared signed chroma pair. Once per frame the converter expands entries into 8-byte RGB555 2×2 tiles in two 0x800-byte SDRAM codebook regions (256 entries each; V1 at +0x800). Colour conversion has no multiplies: `R = clamp(y+2v)≫3`, `G = clamp(y−(u+⌊v/2⌋))≫3`, `B = clamp(y+2u)≫3`, with u the 5th and v the 6th byte, both signed (the SH-2's `mov.b` sign-extends; only the y bytes go through `extu.b`). **Correction (10 October 2026):** this note first said `G = clamp(y−u)≫3`, which dropped the v term, and called it "Sega's integer shortcut". The usual Cinepak green is `y − u/2 − v` (CINEPAK-TD, and ffmpeg exactly): R and B equal ffmpeg's in every value, G is swapped-weight and equals it in 23% of values (discrepancy 49). The 0.996 luma correlation above could not have shown this.
- **Vector stream**: one MSB-first bit per 4×4 block; the 32-bit flag accumulator refills four big-endian bytes from the same stream that supplies index bytes, so flags and indices are interleaved in 32-block groups. Bit = 1 → V4: four index bytes select 2×2 tiles for quadrants TL, TR, BL, BR; bit = 0 → V1: one index, its four pixels painted as quadrant solids. Raster order is row-major, 64×40 blocks, output linear into the staging buffer.
- **Cost shape**: the only per-frame pre-pass is the codebook expansion (≤256 entries); the raster loop is pure byte reads, table lookups and stores — a design aimed squarely at the SH-2's shift-add strengths.

**Egypt — not a codec.** The 4.9 KB SH-2 image contains only the standard dispatchers plus a ~30-instruction display loop (`$06000180` region): copy `0xFA00` words (64,000 = 320×200) from cached ROM `0x0200219C` to the frame buffer `0x24000200`, wait on the FS bit at `0x2000410A`, flip, repeat. File layout closes exactly: MD program `$200-$219C`, **one raw 128 KB RGB frame `$219C-$2159C`**, SH-2 image from `$2159C`. Rendered from the bytes, the frame is a Tutankhamun-mask pharaoh head inside a glass sphere on black — a bitmap-mode test picture, not a movie. (Red/blue may be swapped in my quick RGB555 decoder; content is unambiguous either way.) The "Egypt = CinePak sample" reputation is wrong for this dump; whatever circulated as CinePak footage under that name did not come from these bytes. The `[b1]`/`[b2]` dumps share the same copy block — same program, truncated.

Method note for the book: verification is self-contained (container magic, sample-table chain arithmetic, per-frame structural walk, decoder-constant disassembly); the ffmpeg pass is corroboration, not the evidence the book would cite.

## Runlength Mode Test: the 32X VDP's run-length display mode, driven by a polygon renderer

**This disc tests the VDP's hardware Run Length display mode** (mode register `(M1,M0) = 11`; the app writes mode word `0x8083` to `0x20004100`). The frame buffer holds no pixels: word `0x0000`-onward is the **line table** (word-unit pointers, which is why the renderer stores `address >> 1`), and from `0x24000200` the renderer writes hardware run words `[length = dots−1 | palette index]` — byte-for-byte the format in 32X-HWM §3.3, including the `−1` and the `0xFF`-continuation chaining for runs over 256. There is no expansion pass anywhere: **the VDP expands the runs during display** (PicoDrive implements the mode, hence the clean picture). The "expansion-step hunt" closed with this realisation — the renderer's span output *is* the display format, which is the whole point of the demo. The book's [32X VDP chapter](../../src/32x/vdp.md) already documents the mode; this disc is its shipped-usage evidence.

The renderer that feeds it, plus the most characterful boot sequence of the set:

- **Boot via the VRES handler, with ASCII handshakes.** The handler waits for the 68000 to write `"S_OK"` (`0x535F4F4B`) into COMM1 (`0x20004024`), answers `"M_OK"` (`0x4D5F4F4B`) in COMM0 (`0x20004020`), re-copies its own image per a `[src, dst, len]` descriptor sitting at ROM `$3D4` (`$910`→SDRAM, `0x375BC` bytes — belt-and-braces with the header copy block), switches stack to `$0603FFF8`, and jumps into the main program through a hand-built RTE frame (PC `$06000176`, SR `$F0`). The Slave similarly writes `"SLAV"` (`0x534C4156`) into COMM10 (`0x20004048`) after the same TOCR `$E2`/`$F2` FRT-init sequence seen in Motocross Championship — string-magic COMM handshakes throughout, a nice contrast with MCX's numeric `5`s for the boot chapter.
- **The Slave runs** (does not park, unlike the ECCO demo): the image carries a twin of the renderer at `$06033xxx`, so this is a Master/Slave cooperative program.
- **Ground truth (headless run, frames 150-350).** The test screen shows a **rotating low-poly Sonic the Hedgehog in flat per-triangle debug colours on a pedestal** — a turntable polygon-fill stress test. So "run length mode" = triangle fill via horizontal runs.
- **The engine, end to end.** Per frame, per scanline (224): the renderer writes the line's end pointer into the line table at `0x24000000+line*2`, updates an active-edge table (node `+8` packed x/step, `+12` the x step, `+24` a remaining-lines countdown; edges re-inserted sorted by x through the free-tree), and emits run words `((count−1)<<8) | colour` into `0x24000200+` — the hardware display format directly. The 16-entry grey-blue palette indexes the low byte. The earlier suspicion of DMA-channel programming was wrong: the post-init block builds a **draw primitive** — a node with centre `(0xA0=160, 0xBE=190)`, size/depth `0xFF74`, vertex/model table at `$060333A4` — inserted into the scene list at `$06030A10`. The main loop (`$06030B5C`): rebuild lists, add `0x02D82D80` (fixed-point turntable step) to the object's three angles, transform (`$06030906` scene walk → `$060306C0`/`$06030798`/`$060308A0` edge setup), wait for flip, render runs, flip.
- **Runtime split (PicoDrive, 400 frames).** The Master alone renders: ~306k useful cycles per frame ≈ **80% of one SH-2's whole 60 Hz budget** (23 MHz → 383k cycles), all inside the edge-walk and span-emit loops. The Slave writes `"SLAV"`, double-clears the interrupt flags, then parks forever polling two mailbox longwords at `0x260374F0`/`0x26037530` — a dormant worker with its twin engine linked in but never engaged in this run; the 68000 sits 96% in one wait loop (`$008808FE`). Same single-CPU reality as the ECCO demo, despite the cooperative architecture being present.

## Mars Check Program: the test harness (5 October 2026)

Worked example in `src/howto/reverse-engineering.md`; bibliography key `MARS-CHECK`.

- **Strings**: 300+ test names and OK/ERROR messages from `$1102E` and `$12F70`. Two pointer tables of **plain file offsets**: OK messages from `$129FA` (64 entries; `$0DBA` loads `$8929FA`; e.g. `$12A0E` = number 5 → `$130C8` "DREQ CONTROL REGISTER R/W OK", the 68000-only test's message), ERROR messages from `$12CB6` (63 entries, read by `$1142`/`$0FB2`). Tests print by message number via `bsr $0DBA`. The cross-CPU DREQ tests print `$39` (Master, `MD&SH MASTER DREQ CTL R/W OK`, `$37DC`) and `$3A` (Slave, `$38B4`); COMM names here are byte offsets from `$A15120` (COMM4 = `$A15124`).
- **Register access** is base-relative: `lea $A15100,aN` at 52 sites; no absolute `$A15106` anywhere.
- **Test runner** at `$31B4` (a5 = `$A15100`): walks a table at `$42E8` (count word 19 = 20 entries, longword offsets `$3474`..`$4222`, added to a base at `$34(a6)`), `jsr` each, carry set = fail. RAM `$32(a6)` counts frames (V-int), `$30(a6)` is a second timeout counter.
- **Command protocol**: 68000 writes `$80xx` to COMM0 (Master) or COMM2 (Slave) as a longword `$80xx0000` / `$000080xx`, waits a frame, sets CMD (`bset #0/#1,$A15103`), waits ≤600 frames for the SH-2 to clear it. Commands seen: `$800B` comm-port echo, `$800C` FM cross test, `$800D` DREQ control, `$800E` DREQ source. Phase markers in COMM0: `END ` (`$454E4420`), `SHWR` (`$53485752`, "SH-2 writes now").
- **`$800B` comm test** (`$3474`/`$3518`): walking 1 over 33 shifts written to COMM0 and COMM4 as longwords; the SH-2 echoes into COMM8/COMM12; 5 frames allowed per value.
- **`$800C` FM test** (`$35BC`/`$36CC`): 68000 sets/clears FM, SH-2 reports its view in COMM4 bit 7; then `SHWR`, the SH-2 sets/clears FM and the 68000 checks `$A15100` bit 7. FM is written from both sides and read from the other.
- **`$800D` DREQ control** (`$37DC` → copies `$3876` (512 bytes) to `$FF0000` and runs it there, because it writes RV): SR=`$2700`, writes 7..0 to `$A15107`, waits for COMM4 == value under mask `$87`. SH-2 side `0x06000D68`: until COMM0 = `END `, `mov.b @(7,gbr)` & `$87` → `mov.b r0,@(36,gbr)`. **Expects bit 1 to read back as written on the SH-2 side**; 32X-HWM p.30 (July 1994) shows it as 0. Added to discrepancy 25. PicoDrive stores `d & 7` and returns it to the SH-2, so the test passes there. With the SH-2 mask patched to `$85` (ROM `$AD83`, checksum `$18E` zeroed) PicoDrive's 68000 poll detection puts the 68000 to sleep in the wait loop forever; with it off (`build_nopoll_core.sh`) the test fails with its own error screen (write 07, read 05). See `src/howto/reverse-engineering.md`.
- **`$800E` DREQ source** (`$398C`/`$3A30`): walking 1 from bit 1 (bit 0 untested: word aligned), masked to 24 bits, written to `$A15108`, SH-2 echoes its view via COMM4 longword.
- **SH-2 side** (5 Oct, second pass): Master waits for `SM` (`$534D`) in COMM0 (the runner's `$31C2` writes `SM`/`SS`), clears it, mask = `$0A`, SR = `$10`, then loops: wait for the CMD handler's flag (bit 0 of `@(0,r13)`), index the jump table at `0x06000214` with `COMM & $7F`. Commands → handlers: `$01` comm `0x0600088C`, `$02` FM (byte `0x20004000`, `$80`/`$00`, mask `$80`), `$03` int mask (byte `0x20004001`: 0, `$8F`, `$0F`, mask `$8F`), `$04` H count (byte `0x20004005` walking 1, 8 bits), `$05` PWM timer (word `0x20004030` walking `$100`-`$800`, mask `$F00`), `$06` PWM control (bits 3-0 walking, mask `$F`; then `$80`/`0`, mask `$80` = RTP), `$07` PWM cycle (`0x20004032`, bits 1-11, mask `$FFF`), `$08`-`$0A` PWM FIFOs, `$0D` DREQ ctl echo, `$19` V count, `$1A`-`$1C` H count tests, `$1D` (`$3A` on the 68000) ROM read: `BK00`/`BK01`/`BK10`/`BK11` at `0x220FFFFC`/`0x221FFFFC`/`0x222FFFFC`/`0x223FFFFC`, `$1E` (`$3B`) SCI: sends `$AA` from `0xFFFFFE03`, expects it back via its receive interrupt.
- **Interrupt counts over 30 frames** (68000 `$3D4C`-`$4222`; SH-2 `0x06000DF8`-`0x06000E86`): V with mask `$0A` → 29-32. H with `$0E`, H count 0 → `$1960`-`$1B20` (224/frame). `$8E` (HEN), count 0 → NTSC `$1D00`-`$1F00` (centre 7,680 = 256/frame), PAL `$2472`-`$24CC` (313/frame). `$8E`, count 5 → NTSC `$4D6`-`$52A`, PAL `$5E1`-`$659`. PAL/NTSC chosen by bit 6 of `$40(a6)`. In `src/32x/registers.md`.
- **68000-only tests** (`$1922`-`$1EA6`, messages 0-`$13`): COMM 16-bit walking 1 on all 8 words; FM byte `$80`/`$00` exact; `$A15103` = 3 under mask 3; bank `$A15105` 0-3 then the long at `$9FFFFC` = `BKnn` per bank; DREQ ctl in work RAM (`$1ABA`): 0-7 under mask 7, then 68S + 7 FIFO words → FULL 0, 8th → FULL 1, 68S off → 0 (in fifo.md); source from bit 1, dest from bit 0, 24 bits; length bits 2-15; SEGA TV bit 0; PWM control `$000F` under mask `$F` (TM not tested from the 68000); cycle bits 1-11; PWM FIFOs: EMPTY then not-empty after two writes, then writes until FULL drops (drain check, not a depth test); `$000070` walking 1 over 32 bits.
- **VDP (68000, `$444E`-`$4702`)**: bitmap mode `$A15181` mask `$C3` (PRI 7, 240 6, mode 1-0 — matches the scan, not 32XDK); shift bit 0; fill length 8 bits; fill start 16 bits; VBLK/HBLK/PEN checked against MD H-interrupt line counts with `$70` pointed at `$88082A`; FS bit 0.
- **Frame buffer (68000)**: overwrite test (`$5686`) — `$FFFF` everywhere, write `$00nn` / `$nn00` through `$860000`, expect only non-zero bytes changed. Fill test (`$5F1E`): block *n* length `$FF`−*n* → exactly length+1 zero words (discrepancy 7).
- **Not yet read**: the SH-2-side VDP and frame buffer tests (messages `$51`-`$7E`), sound and display-mode menus, and the `$0DBA`/`$0E1E`/`$0FB2`/`$1142`/`$12DA` message printers.

## Retail banking and Sega's item 8 (2026-10-05)

- **Knuckles' Chaotix** (24 Mbit) runs TI item 8 exactly: `$0009D6` `lea $A130F1,a1` / `tst.b (a1)` / `moveq #0,d0` / `jsr $C0.w`, then copies its own `$880070` into `$70` and selects bank 2 (`move.b #2,$A15105` at `$0009EE`). A second bank-2 write at `$00188C` sits between two waits for COMM0 to read 0, followed by COMM0 = 1. First shipped game in the sources seen doing item 8 (MK2, SWA do not). **Save RAM (5 Oct 2026):** header `RA $F8 $20`, `$200001-$2003FF` (512 odd bytes, over its own ROM: the reason it needs item 8; MK2/SWA declare no save RAM). Load `$03E322`, save `$03E3C0` (pushes SR, ends in `rte`). Both: mask, `$03E44E` = Z80 bus, Z80 `$1C10` = 1 (resume `$03E496` writes `$80`), `$00150015` to `$A15128`/`$A1512C` (the four PWM voice ports), wait COMM0 = 0, `dbf` delay `$2000`; copy 64-byte stub to `$FF0200`; stub sets RV (`$A15107` = 1), `$A130F1` = 3 (load) / 1 (save), 256 bytes on odd addresses, `$A130F1` = 2, RV = 0. Two copies `$200001`/`$200201`, first longword = checksum (seed `$4B52`, 252 bytes, `addx` of the loop counter); load falls back to copy 2. No `$A130F3-FF` refs, no `jsr $D4`. Master FRT init `0x06000884` (OCRA = OCRB = 1, Sega's sample); VRES handler `0x06001250`: clears VRES, reads **byte `0x20004007`** bit 0 (correct), RV = 1 → TOCR OLVLB and loop; RV = 0 → `M_OK` to COMM0, back to `0x060008B4`. In `src/32x/bugs.md`, `src/megadrive/cartridge.md`, `src/howto/large-cartridges.md`.
- **Absolute references to `$A15104`/`$A15105`**: After Burner one (bank 1), Chaotix two (bank 2); MK2, SWA, MCX none (a base-register write would not show).

### ECCO loose ends (resolved)

- **Frame advance** — no pointer patching at all. The stream argument `0x22020000` points at the `FILM` magic itself; the decoder entry reads the container's own header (`@(4)` = header size `0xB84`, so first sample = base+0xB84; `base+16+FDSC size` = the STAB) and walks the sample table with a **16-byte stride** (one `STAB` entry; the "video+audio pairs" this note first said were a misreading) — bounded by the count at STAB+12 (180 video frames, verified numerically against the table). Each pass decodes one sample, then calls the blit/flip; the main loop restarts the movie forever. The `-1` check is on info1, the audio marker of Sega FILM, and it never fires because the file has no audio sample.
- **There is no audio to play** (corrected 10 October 2026; this note said the container's `pcm_s8` track is skipped by the 16-byte walker stride, which was a misreading of the sample table). The 68000 program contains no YM2612, PSG, Z80-bus (`$A11100`/`$A11200`) or PWM writes — its only 32X touches are three `$A15100` adapter-register sites, and the SH-2 image never touches the PWM registers either. The container's `pcm_s8` track is simply skipped by the 16-byte walker stride. A video-only demo despite carrying an audio track.
- **Screen mapping** — no scaling. The blit copies rows of `0x80` longwords (512 bytes = the 256-pixel movie row) from staging to the frame buffer at `0x24002A40`, then skips `0x80` bytes (row pitch 640 = 320 pixels, so 64 blank columns trail each row), for `0x98` = 152 rows of the 160. Five `nop`s sit between longword writes — deliberate pacing of cache-through frame-buffer stores. The `0x2A40` origin (16 rows + 576 bytes) does not divide by the pitch and looks like a hand-tuned constant; the visible placement presumably matches a border drawn on the MD tile side.
- **The Slave does nothing.** Its entry (`$060008120`) clears SR, waits for the longword at `0x20004020` to read 0, and parks in a `bra`-to-self forever (minimal `rte` stubs for interrupts, which just re-clear flags and fall back into the park loop). The whole decode/display pipeline is single-SH-2 — notable for the book: one SH-2 is enough for 256×160 CinePak playback while the 68K draws the chrome.

## Sound paths across the retail cartridges (2026-10-05)

- **Chaotix**: Slave copies 1 KB from cartridge `$7FC00` (`0x0207FC00`) to on-chip RAM `0xC0000000` (`0x06000284`-`0x06000292`), CCR `$19` (two-way) before and after (`0x060002FE`), stack at `0xC0000800`, then calls `0xC0000000` (init: control `$0105`, cycle `$417` = 1,047, both FIFOs filled with 0). Slave dispatcher at `0x060001F8`, table `0x06000220`: slot 3 (levels 6/7, PWM) → `0xC0000004`. Handler: TOCR flip, PWM clear, rotates `0xAAAAAAAA` at `0xC00001EC` and works only on alternate interrupts; four voices, one per port `0x20004028`/`2A`/`2C`/`2E` (read twice until stable, then cleared; low byte = sound number × 16 into a table whose pointer is at `0xC00001F0`; high byte = 4-bit left and right volume, each mapped to 2-32); phase step added to an 11-bit fraction, new 8-bit sample when it passes `$800`; × volume >> 4; the first of the two output samples is the average of the old and new value, the second the new one (2× linear upsampling); sums converted with xor `$400`, and `$7FF`, − `$200`; writes pair 1, polls FULL with a delay loop, writes pair 2. Voice state also in on-chip RAM (`0xC00001F4`, `0xC0000220`, `0xC000024C`, `0xC0000278`). Music side not traced.
- **After Burner Complete**: 68000 copies a 5,888-byte Z80 program from `$97B900` (`$000C2E`). The 68000's request routine (`$009366`) puts each sound number into the first free byte (`$80`) of an 8-byte queue at Z80 `$1800` **and** sends it to the Slave as `$01xx` through `$A15122` + CMD, without waiting for the acknowledgement. The H interrupt (VDP register 10 = `$6E`, table at `$000F9A`: twice a frame; 1,295 entries in the first 1,000 frames from power-on) bumps Z80 `$A016FF`, forwards a non-zero Z80 byte `$A016FD` as `$0203`, then sends the `$0200` tick: both sequencers are paced by one interrupt. The `$A016FF` byte advances about 115 per frame in PicoDrive, so the Z80 writes it too.
- **Star Wars Arcade**: 68000 copies a 409-byte Z80 program from `$88FE68` (`$00EF5E`). Z80 (decoded by hand): main loop polls `$0FFA` (call `$0120`: if Timer A has overflowed, re-arm it with `$27` = `$15` and write the next byte of a 256-byte buffer at `$0E00` to the DAC, index `$0FFB`, end `$0FFC`) and `$0FFF` (call `$0026`: run a list of YM2612 writes at `$1000` left by the 68000; busy-wait on the YM status before each write). The 68000 writes the PSG itself (12 sites, `$00ECD6`-`$00F4A8`).
- **Mortal Kombat II**: loads a 27-byte Z80 stub that sets the Z80 bank register (`$0407AE`), then a 2 KB Z80 program to Z80 `$0400` from `$93C108` (`$0408CC`). Not traced further.

### Chaotix Slave, corrected (2026-10-05)

- The "~302k cycles at `0xC000xxxx` pseudo-PCs" in the runtime notes above are real addresses: the Slave's PWM mixer runs from on-chip RAM (two-way mode). There is no `sleep` in the program (the six `sleep` decodes are data).
- Slave main loop `0x060002D4`-`0x060002E8`: reads a command byte from `0x20004005` (the SH-2-side H count register, free because H interrupts are never enabled), dispatches through a 3-entry `bsrf` table at `0x060002F0`, writes 0 back. Command 0 = a 99-pass `dt` delay then poll again; 1 = CCR `$19`; 2 (`0x0600032C`) = 216 auto fills of 145 words of 0, start `$508`, step `$100`, waiting on FEN (`0x2000410B` bit 1) before and after each.
- The Master posts command 2 at `0x06004B12`, runs its drawing calls, and waits for the byte to read 0 at `0x06004B9A`. Frame-buffer addresses appear only in Master-run code. So: Master draws, Slave clears and plays sound. `src/howto/profiling.md` and `src/patterns/bus.md` corrected.
- **Layering (PicoDrive, attract frames 4300 and 4400):** bitmap mode `$8081` (PRI 1, packed pixel), line table at 256-word pitch (line *n* at word `($n$ + 1) × $100`), palette entry 0 = `$A489` (through bit set) plus 122 more through entries. The frame buffer holds only characters, sparkles and a ring on a field of entry 0: the same picture as MK2's PRI 0 scheme, by the opposite setting. In `src/32x/compositing.md`, `src/patterns/layering.md`.
