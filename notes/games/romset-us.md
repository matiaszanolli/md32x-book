## VRES handlers read (6 October 2026)

- VRD (SH-2 image at $020000): Master 0x060004A4, Slave 0x06000614 (dispatch tables at 0x06000714/0x06000778).
  Master: clear VRES, byte 6, COMM0 = 0, 'VRES' -> COMM12, DMAOR = 0, CHCR0 = 0 then $44E0, bra restart.
  Slave reads "RV" through r1 = its own address (dispatcher jsr @r1), i.e. byte $84 at 0x0600061A: always normal path.
  68000 waits for 'VRES' at $A1512C: $0008A8-$0008B6.
- Space Harrier (image $010000): Master 0x060011F8, Slave 0x060001C8. Same as After Burner Complete's
  (Slaves identical but for SP; Masters identical from the VRES clear on; SH's Master also flips TOCR first).
  68000 wait loop $00085E-$00086C (AB: $00086C-$00087A, byte-identical but one PC-relative displacement).
- 'VRES' as code appears only in AB, SH, VRD (Brutal's match is French text "PAUVRES").
- Kolibri Master $009204 (table entry $0091F4): flag store to 0x26033200, then the TIA1 listing exactly.
- Tempo Master $080678: TIA1 listing, but CHCR0 address load at $080694 is overwritten before any store.
- Doom Master $04DD78 (runs from cartridge): RLT's handler ($000B40) without the RV test; clears COMM8/COMM12.
- Sega's initial program ($3F0-$7FF) is identical in every cartridge and sample except the ECCO demo.
- Comparison pitfall: running two `sh-elf-objdump` extractions concurrently into one temp file gives
  identical (wrong) columns; extract to separate files.
