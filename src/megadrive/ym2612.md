# YM2612 FM synthesis

The Mega Drive's melody and harmony chip is Yamaha's YM2612: six independent voices, each built from four sine-wave operators an algorithm wires into modulators and carriers, plus a low-frequency oscillator, two timers, and an 8-bit sample channel that replaces voice 6. This page is the chip reference: what FM synthesis means here, how the registers are reached and in what order, the register map part by part, voice 3's special mode, the DAC, and the timers. Who may write the chip and when — the bus rules — is in [The Z80 and sound](sound.md#the-rules); this page is about the registers themselves.

Two documents describe the chip, both converted into one file: Sega's own manual chapters, written as a friendly tutorial, and Yamaha's application manual, denser and more precise [MD-SWM, FM sound source overview; MD-SWM, YM2612 application manual]. Where they disagree, both are quoted.

## Operators, algorithms, envelopes

An **operator** is one sine-wave generator: a frequency, an envelope, and an output. Four belong to each channel. An **algorithm** is one of the eight ways to wire them: in the FM arrangements, one operator's output bends the phase of the next (a *modulator*), and the last one or more simply output their wave (the *slots*, or *carriers*). A slot's envelope sets the note's loudness; a modulator's envelope and frequency shape its timbre. Operator 1 can also feed back into itself, eight depths of it, which thickens a single operator into something like a sawtooth [MD-SWM, a little bit about operators; MD-SWM, YM2612 application manual §2-2].

```
Algorithm 0            Algorithm 2            Algorithm 7
1 → 2 → 3 → [4]        1 → [3]                [1]
                       2 → [4]                [2]
Algorithm 4                                    [3]
1 → [2]                Algorithm 5            [4]
3 → [4]                1 → 2, 1 → [3],
                       1 → [4]
```

Four operators make 1 (algorithm 0), 2 (algorithms 2-4), 3 (algorithm 5) or 4 (algorithm 7) carriers. Sega's instrument suggestions: algorithm 0 for distortion guitar and aggressive bass, 2 for bass, brass, piano and woodwinds, 4 for drums and bells, 5 for brass and organ, 7 for pipe organ [MD-SWM, algorithms]. The envelope of each operator is the familiar shape — attack, first decay, sustain, release — set by six numbers:

| Field | Register | Meaning |
|-------|----------|---------|
| TL | `$40`+ | Total level, the ceiling: `$00` loudest, `$7F` is 96 dB down, about 0.75 dB per step |
| AR | `$50`+ | Attack rate, the rise at key on |
| D1R | `$60`+ | First decay rate, down from the ceiling |
| D1L | `$80`+ | The level the first decay settles at (compare with TL after multiplying by 8) |
| D2R | `$70`+ | Second decay rate, the slow tail that lasts while the key is held |
| RR | `$80`+ | Release rate, the final decay at key off |

All rates are five-bit numbers, 0-31; rate 0 in AR, D1R or D2R means "do not move" (an attack that never rises, a decay that never falls). RR is stored in four bits and behaves as the value doubled, plus one — 8, 10, 12 … 31. **RS** (rate scaling, the top bit pair of `$50`) shortens every rate as the note gets higher: the chip takes the key code from the top five bits of the channel's frequency setting, and the effective rate is `2 × rate + KC / 2^RS` (rounding down) — the reason a piano's high notes die faster than its low ones [MD-SWM, RS/AR; MD-SWM, YM2612 application manual §2-4].

Two more per-operator bits: **AM** (top bit of `$60`) lets the LFO tremolo this operator, and **SSG-EG** (`$90`+) replaces the envelope's decay stages with the SSG sound chip's repeating envelope patterns. Sega's manual calls that register proprietary and says to leave it at 0 <span class="tag manual">manual</span> [MD-SWM, register 90H+]; Yamaha's own manual documents it — set AR to `$1F` first, and RR behaves normally — and PicoDrive implements the patterns [MD-SWM, YM2612 application manual §2-4-2; PICODRIVE, pico/sound/ym2612.c]. Nothing needs it; starting from Sega's advice costs nothing.

## Reaching the registers

The chip is behind the Z80 bus: `$A04000-$A04003` for the 68000 (bus held), `$4000-$4003` for the Z80, byte access only [MD-SWM §4.5]. Four locations, two per half:

| | Address (68000) | Address (Z80) | Part |
|---|---|---|---|
| Address | `$A04000` | `$4000` | Common and channels 1-3 |
| Data | `$A04001` | `$4001` | |
| Address | `$A04002` | `$4002` | Channels 4-6 |
| Data | `$A04003` | `$4003` | |

To write a register: send its address to the address port, then the data to the data port, same half. Reading any port returns one status byte [MD-SWM, read data]:

| Bit | Meaning |
|-----|---------|
| 7 | Busy: 1 while the chip is still digesting the last write |
| 2 | Timer overflowed (either timer; the enable bits below choose whether this is set) |
| 1 | Timer B flag |
| 0 | Timer A flag |

The busy flag is polled before every write. Sega's bulletin is strict about **where**: read it at `$4000` and nowhere else — reading it at `$4001` can report "not busy" while the chip is busy, and sound dies during play <span class="tag manual">manual</span> [MD-TB #11; MD-SWM, sound software manual §5]. Two more writing rules: registers that are ganged into a longer number (timers, frequencies) are written high half first, low half second; and the chip wants a moment between one register's writes and the next — the busy flag is the measure of it [MD-SWM, writing to the FM-2612].

## The common registers, `$21`-`$2B`

| Register | Contents |
|----------|----------|
| `$22` | LFO: bit 3 on/off, bits 2-0 speed |
| `$24`-`$25` | Timer A period, 10 bits (high byte in `$24`) |
| `$26` | Timer B period, 8 bits |
| `$27` | Timer control and channel 3 mode |
| `$28` | Key on / key off, one channel at a time |
| `$2A` | DAC sample byte |
| `$2B` | DAC enable |

**The LFO** (`$22`) wobbles pitch and/or loudness of any channel that asks for it (the per-channel sensitivities live in `$B4`+; the per-operator AM switch in `$60`+). Its eight speeds [MD-SWM, register 22H]:

| Speed | Rate | | Speed | Rate |
|-------|------|---|-------|------|
| 0 | 3.98 Hz | | 4 | 6.88 Hz |
| 1 | 5.56 Hz | | 5 | 9.63 Hz |
| 2 | 6.02 Hz | | 6 | 48.1 Hz |
| 3 | 6.37 Hz | | 7 | 72.2 Hz |

**Key on/off** (`$28`) drives one channel per write: bits 4-7 set slots 1-4 (Sega's own software always moves all four together), bits 2-0 pick the channel, encoded with gaps: 0-2 are channels 1-3, 4-6 are channels 4-6 — codes 3 and 7 do nothing [MD-SWM, register 28H]. A note's life is: write the voice's registers, key on, make sound, key off — the envelope's RR stage then finishes it.

**`$27`'s top two bits are one field, channel 3's mode** ([discrepancy 36](../appendices/discrepancies.md)): `00` is normal, `01` gives the channel's four operators separate frequencies (special mode, next section), `10` does the same and adds CSM, and `11` acts like `01` [GENDEV-YM, 29 June 2008]. CSM, composite sinusoidal modelling, is a mode where every overflow of timer A keys channel 3's operators on and at once off again. It works only while timer A is loaded (bit 0), and it skips any operator already keyed on through `$28`. Since the key-off follows at once, an operator only sounds if its attack rate is `$1E` or `$1F`, which start the envelope at its total level; TL and RR then shape the sound [GENDEV-YM, 29 June 2008]. Nuked-OPN2, built from the die, decodes the field the same way, and so do Genesis Plus GX, BlastEm and MAME <span class="tag emulator">emulator</span> [NUKED-OPN2, ym3438.c]. PicoDrive and ares give separate frequencies but have no CSM [PICODRIVE, pico/sound/ym2612.c]. The documents get this wrong in two ways. Sega's manual calls every value with bit 7 set illegal [MD-SWM, register 27H]. Yamaha's application manual swaps the labels, giving `01` as CSM and `10` as "effect sound" [MD-SWM, YM2612 application manual §2-1-1]. Write `01` for separate frequencies, and `10` only if you want CSM.

The low six bits of `$27` run the timers, two bits each, timer B's pair left of timer A's [MD-SWM, register 27H]:

| Bits | Name | Effect of 1 |
|------|------|-------------|
| 1, 0 | LOAD B, A | Start the timer counting |
| 3, 2 | ENABLE B, A | An overflow sets the status flag (without it, the timer cycles silently) |
| 5, 4 | RESET B, A | Clear the status flag; the bit self-clears |

## Per-operator registers, `$30`-`$9E`

Every operator of channels 1-3 has one register at each of six offsets; channels 4-6 repeat the same layout through part II's ports. Within an offset, the operator is the high part of the register number and the channel the low: `$30`/`$31`/`$32` are operator 1 of channels 1/2/3, `$34`-`$36` operator 2, `$38`-`$3A` operator 3, `$3C`-`$3E` operator 4; part II is identical for channels 4-6 [MD-SWM, registers 30H-90H].

| Offset | Bits |
|--------|------|
| `+$30` | Detune (3 bits, sign-magnitude) and multiple (4 bits): the operator's frequency as a multiple of the channel's |
| `+$40` | TL: total level, 7 bits |
| `+$50` | RS (2 bits) and AR (5 bits) |
| `+$60` | AM switch (1 bit) and D1R (5 bits) |
| `+$70` | D2R (5 bits) |
| `+$80` | D1L (4 bits) and RR (4 bits) |
| `+$90` | SSG-EG (4 bits) |

The multiple runs ½, 1, 2 … 15 for values 0-15. Detune bends that by ±3 small steps of a sign-and-magnitude field, each step a fraction of a percent — enough to fatten two identical operators into a chorus [MD-SWM, registers 30H+].

## Per-channel registers, `$A0`-`$B6`

Three registers each, one per channel, channels 4-6 again in part II:

| Register | Contents |
|----------|----------|
| `$A0`+ | Frequency number, low 8 bits |
| `$A4`+ | Block (3 bits, at bits 5-3) and frequency number, high 3 bits |
| `$B0`+ | Feedback (3 bits) and algorithm (3 bits) |
| `$B4`+ | Stereo L, R enables, AMS (2 bits), FMS (3 bits) |

**Frequency** is an 11-bit number inside one octave, and the 3-bit **block** picks the octave: eight octaves. The pair is written high register first [MD-SWM, registers A0H+, A4H+]. The frequency number for the twelve equal-tempered notes of one octave [MD-SWM]:

| Note | F-num | Note | F-num | Note | F-num |
|------|-------|------|-------|------|-------|
| C | 617 | F | 823 | A | 1037 |
| C# | 653 | F# | 872 | A# | 1099 |
| D | 692 | G | 924 | B | 1164 |
| D# | 733 | G# | 979 | | |
| E | 777 | | | | |

The general formula from Yamaha's manual is frequency number = `144 × f × 2^20 / M / 2^(block-1)`, with M the chip's input clock; its printed `2^22` is a conversion slip, as its own worked example (A4 = 440 Hz at M = 8 MHz, block 4 → 1038) only works with `2^20` [MD-SWM, YM2612 application manual §2-3-1].

**Stereo** (`$B4` bits 7-6) routes a channel to the left or right output — on the original console model, audible only through the headphone socket [MD-SWM, register B4H+; MD-SWM, FM sound source overview]. The same register's **AMS** and **FMS** set how hard the LFO swings this channel's loudness (0, 1.4, 5.9 or 11.8 dB) and pitch (0 to ±80% of a semitone in seven steps) [MD-SWM, register B4H+].

## Channel 3's special mode

Normally every operator of a channel derives its frequency from one frequency number — the multiple and detune per operator shape it from there. Channels 3 and 6 can instead take four independent frequencies, one per operator: channel 3 operator 1 keeps `A2`/`A6`, and operators 2-4 move to `A8`/`$AC`, `A9`/`$AD`, `AA`/`$AE` (channel 6 likewise through part II) [MD-SWM, register 27H, registers A8H+]. This is the percussion trick: a drum's partials are not whole-number multiples of a fundamental, and separate frequencies can place them anywhere. Sega's note is that the mode exists on the last channel of each half, and only bit 6 of `$27` is needed to get it [MD-SWM, register 27H].

## The DAC

Setting bit 7 of `$2B` switches voice 6's hardware from FM to an 8-bit digital-to-analogue converter: each byte written to `$2A` becomes the output voltage, as offset binary (`$80` is the centre) [MD-SWM, register 2AH; MD-SWM, YM2612 application manual §2-1-2]. What surrounds that one line is all discipline:

- FM voice 6 is silent while the DAC is on; only voice 6's stereo bits in `$B4` still apply [MD-SWM, register 2BH].
- There is no timing help. The CPU or Z80 writes each sample at the sample rate, by hand; evenly spaced writes are the whole of the sound quality. That is why sample players live on the Z80 with its steady 3.58 MHz loop, and why every bus request during playback dents the sample [MD-SWM, FM sound source overview].
- The chip's own rating is modest: the output converters are 9-bit, so about 54 dB of the level control's 96 dB is truly audible, and Yamaha rates the sample function at 55.5 kHz — far above what a Z80 feeding it byte by byte can sustain for long [MD-SWM, YM2612 application manual §1-1, §2-4-3].

## The timers

Two down-counters a program can use as its rhythm: **Timer A**, 10 bits across `$24` (high) and `$25` (low), and **Timer B**, 8 bits in `$26` [MD-SWM, registers 24H-26H]. Sega's figures for the Mega Drive:

| Timer | Period | Range |
|-------|--------|-------|
| A | 18 µs × (1024 − value) | 18 µs to 18.4 ms |
| B | 288 µs × (256 − value) | 0.288 ms to 73.4 ms |

Yamaha's formulas are the same shape with the master clock explicit: `72 × (1024 − NA) / M` and `1152 × (256 − NB) / M` [MD-SWM, YM2612 application manual §2-1-1]. Sega's numbers correspond to M = 4 MHz; at the 8 MHz the chip is specified for, a step is half as long. Which figure a console matches is untested (see Open questions).

The timers **do not interrupt**. The chip has an IRQ pin for them, but on the Mega Drive nothing connects it to the CPUs: the status byte's flags, enabled in `$27` and read at `$4000`, are the only way to know a timer fired [MD-SWM, FM sound source overview; MD-SWM, YM2612 application manual §1-4]. A driver that wants a faster rhythm than the Z80's one-per-frame interrupt polls timer A here — the classic sample-player's clock.

## A whole note, start to finish

Sega's tested power-on example, one note of a piano voice on channel 1 [MD-SWM, FM sound chip register example]. First the globals: `$22` = 0 (LFO off), `$27` = 0 (normal mode), `$28` = 0-2 then 4-6 (key every channel off), `$2B` = 0 (DAC off). Then the voice, sixteen operator registers of channel 1: detune/multiple `$30`=`$71`, `$34`=`$0D`, `$38`=`$33`, `$3C`=`$01`; levels `$40`=`$23`, `$44`=`$2D`, `$48`=`$26`, `$4C`=`$00`; attack `$50`=`$5F`, `$54`=`$99`, `$58`=`$5F`, `$5C`=`$94`; decays `$60`-`$6C` = `$05`/`$05`/`$05`/`$07`, `$70`-`$7C` = `$02`; sustain/release `$80`-`$88` = `$11`, `$8C`=`$A6`; SSG-EG all 0. Then the channel: `$B0`=`$32` (feedback 3, algorithm 2 — one modulator stack, one carrier), `$B4`=`$C0` (both outputs). To play: key off (`$28`=`$00`), set the note — `$A4` then `$A0`, high first — key on all four slots (`$28`=`$F0`), hold, and key off (`$28`=`$00`) to let the release finish.

Every one of those writes is address port, busy wait, data port; the pauses between registers are why a 68000 writing the chip directly, as Virtua Racing Deluxe does, pays so dearly per note, and why the other drivers in [The Z80 and sound](sound.md#who-does-the-work) hand the chip to the Z80 [VRD-NOTES, analysis/SOUND_DRIVER_ARCHITECTURE.md].

## Open questions

- Did any shipped game use CSM? PicoDrive's disabled code names Vectorman 2, but nothing confirms it.
- Do Sega's timer steps (18 µs, 288 µs) match the console, or is the effective clock the chip's 8 MHz with 9 µs and 144 µs steps?
- The frequency-number formula's printed `2^22` against its own `2^20` worked example: worth a tuning check on hardware before relying on the formula's last digit.
