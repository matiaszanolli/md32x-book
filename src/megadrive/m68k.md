# The 68000 for Mega Drive work

The Mega Drive's main processor is Motorola's 68000: a 16/32-bit CPU running at 7.67 MHz on NTSC machines and 7.60 MHz on PAL [MD-SWM §4.1], with no cache and no memory management, so every wait state and every competing bus master is visible in the program's speed. This page covers only what a Mega Drive programmer needs from Motorola's manual: the programming model, the exception and vector mechanism, the addressing modes ranked by what they cost, the instructions whose cost dominates hot loops, and how the VDP and the other bus masters change the picture. It is a companion, not a substitute: the full instruction descriptions are in the Programmer's Reference [M68K-PRM].

One caution about that reference: our copy is the *family* manual, which also describes the 68020 and later chips. Scaled indexing, memory-indirect addressing and 32-bit divide forms marked as later-chip features do not exist on the plain 68000. Where it notes how the 68000 treats a scaled index — the scale bits are ignored, the access lands somewhere unintended — is exactly the kind of trap this page exists to keep code away from [M68K-PRM §2.3].

## The programming model

Sixteen 32-bit registers: eight data registers, D0-D7, for arithmetic, and eight address registers, A0-A7, for pointers. Data-register operations work on bytes, words and longwords; address-register operations on words and longwords only. A7 is the stack pointer — after reset, the supervisor stack pointer, loaded from the first entry of the vector table [M68K-PRM §3; M68K-PRM §2].

The status register has a byte of condition codes — carry (C), overflow (V), zero (Z), negative (N), extend (X) — and above it the supervisor bit, the trace bit, and a three-bit interrupt mask. The mask, 0-7, holds off every interrupt at or below its level; level 7 cannot be masked. On the Mega Drive the levels in use are 6 for the vertical interrupt, 4 for the line interrupt and 2 for the external interrupt, each covered in [Timing, interrupts and counters](vdp-timing.md) [MD-SWM §2.6; GENVDP §4].

**Supervisor versus user mode** exists on the chip: the CPU starts in supervisor mode at reset, privileged instructions (`RTE`, `STOP`, `RESET`, writes to SR and USP) trap in user mode, and an exception switches back to supervisor [M68K-PRM §3]. Nothing in a Mega Drive asks it to leave supervisor mode — there is no operating system to return to — so in practice the privilege rules matter only as trivia, and the interrupt mask in SR is the part games touch.

The 68000 is **big-endian**, and word and longword accesses must be aligned: a word access at an odd address raises the address-error exception, not a wrong result. On the Mega Drive that shapes the whole map — byte-wide devices sit on odd addresses (`$A10001` and friends, see [Controllers and I/O ports](io.md#the-registers)), the VDP takes word writes (bulletin 13, in [Sega's technical bulletins](errata.md#rules-that-changed-how-code-is-written)), and code that treats the machine as byte-addressable everywhere dies in vector 3.

## The vector table and exceptions

Exceptions are dispatched through a table of 64 longwords at `$000000`, and on the Mega Drive the cartridge supplies it [M68K-PRM §3]. Entry 0 is the initial stack pointer, entry 1 the reset program counter; the rest pair a vector number with a handler address. The vectors a Mega Drive program can actually meet:

| # | Exception |
|---|-----------|
| 0, 1 | Initial SSP, initial PC |
| 2 | Bus error |
| 3 | Address error (odd or misaligned access) |
| 4 | Illegal instruction |
| 5 | Divide by zero |
| 6, 7 | `CHK`, `TRAPV` |
| 8 | Privilege violation |
| 9 | Trace |
| 10, 11 | Line-A, line-F (unassigned opcode ranges) |
| 15 | Uninitialized interrupt vector |
| 24 | Spurious interrupt |
| 25-31 | Interrupt autovectors, levels 1-7 |
| 32-47 | `TRAP #0`-`#15` |

Source: [M68K-PRM §3]. A shipped table shows the habit: Aerobiz fills every slot, including the reserved ones, each pointing at a stub — initial stack `$00FFF000` (just under the top of the 64 KB work RAM), entry `$200`, and sixteen exception handlers packed into `$F84-$FD2` [AB-DISASM, header.asm]. Interrupts arrive as levels on the IPL pins, not as individual vectors: the 68000 masks by level, then takes the matching autovector — which is why the VDP's three interrupts ride levels 6, 4 and 2 rather than vector numbers of their own [M68K-PRM §3; GENVDP §4].

## Addressing modes, ranked by cost

The rule behind every ranking: the 68000 has no cache, and every memory reference is a bus cycle paid in full. Fewer memory references, cheaper instruction — a register-only operation touches nothing but the register file; every level of indirection adds a read.

| Mode | Syntax | Cost shape |
|------|--------|------------|
| Data / address register direct | `D0`, `A0` | Cheapest: no bus cycle |
| Register indirect | `(A0)` | One read or write |
| Indirect with post-increment / pre-decrement | `(A0)+`, `-(A0)` | One access, register updated free — the streaming modes |
| Indirect with displacement | `$12(A0)` | One extension word fetched, one access |
| Indirect with index | `$12(A0,D0.W)` | Two extension words, an add, one access |
| Absolute short / long | `$FFFF8000` / `$A15100` | One fetch (sign-extended) / two fetches, one access |
| Program-counter relative | `$10(PC)`, `$10(PC,D0.W)` | One extension word, one add — relocatable, and the basis of position-independent code |
| Immediate / quick | `#$1234`, `#1` | The constant is fetched with the instruction; quick forms encode it in the opcode |

Source: the mode set is [M68K-PRM §2]. Two uses dominate shipped code: post-increment with pre-decrement pairs walk buffers forwards or backwards in one instruction (`move.b (a0)+,(a1)+` is the copy loop of the machine, and the direction choice is how Aerobiz's overlap-safe block copy works), and PC-relative indexing drives jump tables: one `add.w`, then a `bra.w` or `jsr` through `offset(PC,D0.W)` dispatches on a computed index — the whole controller-type dispatch in [Controllers and I/O ports](io.md#telling-devices-apart-the-peripheral-id) is eight `bra.w` entries reached that way [AB-DISASM, InputCaseDispatch.asm].

## Instruction costs that matter in hot loops

Motorola's User's Manual times every instruction in clock periods, and those are the figures to plan with <span class="tag manual">manual</span> [M68K-UM §8]. It assumes every memory access takes four clocks, so each word the instruction fetches, reads or writes costs four, and anything that slows an access, such as the VDP or the Z80 holding the bus, adds to the total. A selection:

| Instruction | Clocks | Notes |
|-------------|--------|-------|
| `NOP`, register `MOVE`, `ADD`, `SUB`, `AND`, `OR` (byte, word) | 4 | One word fetched, nothing else |
| `MOVEQ`, `ADDQ`/`SUBQ` to a data register | 4 | Long `ADDQ`/`SUBQ`: 8 |
| `MOVE.W (An)+,(An)` | 12 | Read and write one word each |
| `Bcc` | 10 taken; 8 not taken (byte offset), 12 (word offset) | `BRA` 10, `BSR` 18 |
| `DBcc` | 10 looping; 14 when the count runs out; 12 when the condition is true | |
| Shift or rotate a register by *n* | 6 + 2*n* (byte, word); 8 + 2*n* (long) | One bit in memory: 8 plus the address |
| `MULU`, `MULS` | 38 + 2*n*, at most 70 | Plus the operand's address |
| `DIVU` | at most 140 | Best and worst within 10% |
| `DIVS` | at most 158 | Best and worst within 10% |
| `MOVEM` registers to memory | 8 + 4*n* (word), 8 + 8*n* (long) for *n* registers, with `(An)` or `-(An)` | |
| `MOVEM` memory to registers | 12 + 4*n* (word), 12 + 8*n* (long), with `(An)+` | |
| `RTS`, `RTE` | 16, 20 | |
| Taking an interrupt | 44 | Stacking, the vector fetch and the handler's first fetch |

Sources: [M68K-UM Tables 8-1 to 8-14]. Addressing modes add their own time: nothing for a register, 4 clocks for `(An)` or `(An)+`, 6 for `-(An)`, 8 for `(d16,An)` or an absolute short address, 12 for an absolute long one, and twice the reads for a long operand [M68K-UM Table 8-1].

The cheap end needs little advice: register operations and short branches cost a fetch or two, and `DBcc` closes a countdown loop in one short instruction. Three costs shape everything else:

**Multiply and divide are an order of magnitude dearer than adds.** `MULU`/`MULS` are 16×16 → 32 operations. They take 38 + 2*n* clocks, where for `MULU` *n* is the number of 1 bits in the source operand, and for `MULS` the number of changes between 0 and 1 along the source with a 0 appended below it. So a multiplier with few bits set is faster, and the worst cases, 70 clocks, are `$FFFF` for `MULU` and `$5555` for `MULS` <span class="tag manual">manual</span> [M68K-UM §8.3]. `DIVU.W` and `DIVS.W` divide 32 by 16, leaving the quotient in the low word and the remainder in the high word of the destination. They take at most 140 and 158 clocks, and Motorola puts the best case within 10% of that, so there is no cheap divide to hope for [M68K-UM §8.3]. Aerobiz's analysis uses the same worst cases [AB-DISASM, math modules]. The divide rules matter as much as the cost: division by zero traps through vector 5, and an overflow — a quotient that will not fit in 16 bits — sets V and leaves the operands untouched, which is a detectable, branchable event rather than a wrong answer [M68K-PRM §4, DIVU].

**`MOVEM` moves a list of registers in one instruction** [M68K-PRM §3, Table 3-2]. It is how interrupt handlers pay for themselves: `movem.l d0-d7/a0-a6,-(sp)` at the top and the matching reload at the bottom saves and restores everything used, and it is the first instruction of nearly every register-heavy routine in Aerobiz's input and DMA paths [AB-DISASM, ReadPortByte.asm].

**Shifts and rotates are cheap in registers and one-shot in memory**: a register shift moves 1 to 8 bits in an instruction whose cost grows with the count, while a memory operand shifts exactly one bit — a memory shift loop is a way to make a slow loop [M68K-PRM §3].

And one absence worth naming: the 68000 has no instruction that touches two memory operands. Every arithmetic result passes through a register, which is why the dialect of Mega Drive code reads `move.w (a0),d0; add.w d1,d0; move.w d0,(a1)` — and why compiler-generated 68000 looks so register-shuffly.

## Arithmetic the shipped way

Aerobiz's math module, whose multiply alone is called from 204 places in the game, is a complete lesson in dodging the costs above [AB-DISASM, math modules; analysis/FUNCTION_REFERENCE.md]:

- **A 32×32 multiply as up to three `MULU`s, usually one.** The low 32 bits of the product need only the three cross terms of the half-words; the high×high term cannot reach them. Each cross term whose operand half is zero — the common case for game values — is skipped entirely [AB-DISASM, Multiply32.asm `$3E05C`, 204 call sites].
- **A three-tier unsigned divide.** A divisor under `$10000` tries one `DIVU.W`; on overflow it finishes with schoolbook long division — high word, then remainder:low word, two `DIVU`s; a divisor of `$10000` or more falls back to sixteen rounds of shift-and-subtract with `ADDX`, since only a 16-bit quotient is wanted [AB-DISASM, UnsignedDivide.asm `$3E0C6`].
- **Signed divide and modulo with the same fast path**, taking absolute values on the slow route and restoring the sign with one toggled byte; the modulo keeps the dividend's sign, as C does [AB-DISASM, SignedDiv.asm `$3E08A`, SignedMod.asm, UnsignedMod.asm].
- **An overlap-safe block move** that compares the pointers once and then copies backwards with `-(a0),-(a1)` when the destination sits above the source — the textbook `memmove`, in the minimum number of instructions [AB-DISASM, MemMove `$45B2`].

The pattern in all four: test for the cheap case first, fall back only when the numbers force it, and never pay the wide operand cost when the narrow one is legal.

## What the VDP and DMA do to real speed

The cycle counts above are what the CPU costs alone. The Mega Drive rarely grants it that solitude:

- **A DMA from 68000 memory stops the 68000 completely** until the transfer ends — the VDP owns the bus [MD-SWM §2.7]. How long that lasts depends on where it runs: during the display, Sega's own figures show VDP DMA is no faster than a 68000 copy loop, while vertical blank roughly doubles the rate. Big transfers belong in vertical blank; see [DMA](vdp-dma.md#how-much-fits-in-a-frame).
- **The Z80 borrows the bus** for every access through its bank window, and the 68000 waits meanwhile — a little, per byte, all the time a sample stream runs [MD-SWM §4.5; [Z80 bus control](z80.md#the-bank-window-from-the-z80-side)]. BlastEm charges the 68000 8 clocks for each such access, a figure its source marks as an estimate still to be checked with a logic analyser <span class="tag emulator">emulator</span> [BLASTEM, genesis.c].
- **Memory refresh takes a little of every stretch of time.** The emulators stall the 68000 briefly at regular intervals to stand for refresh of the console's dynamic RAM: BlastEm 2 clocks in every 128 on any access outside the I/O area, ares 2 in every 128 on the cartridge and 3 in every 132 on work RAM. That is 1.5-2.5% off the table figures for code running from ROM or RAM <span class="tag emulator">emulator</span> [BLASTEM, genesis.c `gen_update_refresh`; ARES, ares/md/bus/inline.hpp, cpu/cpu.hpp]. No manual in the sources gives a figure. Genesis Plus GX models none.
- **Each access to the Z80's area costs one extra clock**, in all three emulators <span class="tag emulator">emulator</span> [GPGX, core/mem68k.c; ARES, ares/md/bus/inline.hpp; BLASTEM, genesis.c]. Genesis Plus GX and ares give crashes in Pac-Man 2's sound driver as the reason they added it.
- **The 68000's own writes to the VDP** are word writes to two ports, and the ROM-DMA trap (the command's final write must be fetched from RAM) is a fetch-timing effect, not a software rule [MD-SWM §2.7; [DMA](vdp-dma.md#three-rules-when-the-source-is-rom-or-ram)].

The practical accounting habit, and the one the case studies use, is to measure code where it runs: profiler numbers from an emulator include all of this interference, which is why they are the currency of the [profiling](../howto/profiling.md) and [case study](../patterns/case-study-vr.md) chapters rather than table cycles alone.

## Open questions

- How long does a long DMA stall the 68000 on each console model? No source measures a model against another. The emulators follow Sega's table to within one byte a line ([discrepancy 43](../appendices/discrepancies.md)) and model no difference between models.
- Do Motorola's figures hold on a console for the Mega Drive's ROM and work RAM, and what do refresh, the Z80's area and the Z80's bank window really add? The emulators' figures above are their authors' models; BlastEm's 8 clocks for a bank window access is marked as an estimate.
